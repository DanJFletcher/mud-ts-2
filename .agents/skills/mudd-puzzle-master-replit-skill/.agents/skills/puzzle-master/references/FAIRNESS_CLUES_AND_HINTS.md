# Fairness, clarity, experiment feedback, hints

## Clue ledger per inference

For each necessary deduction, write: `inference_id`, `truth`, `why the clue supports it`, `where discovered`, `sensory modality`, `access restrictions`, `alternate clue locations`, `testable prediction`. Identify load-bearing inference bottlenecks. For mandatory access apply Three Clue Rule *as a robustness heuristic*, not a mathematical guarantee of success.

Clues should be **independent**—a plaque, a mechanical reaction and an NPC's observation are better than three differently worded plaque paragraphs. Don't give all hints automatically; player discovery is the reward. Distinguish discovery clues from verification feedback and solution spoilers.

## Feedback matrix

Every registered action has one of: valid progress, valid but ineffective, meaningful failed attempt, already completed, temporarily blocked, invalid/unrecognized, not permitted. Each receives truthful, contextual feedback. Examples: “The flywheel shudders, but pressure still pushes against the latch” is better than “Wrong answer.” Unknown verbs should surface suggested valid actions or refer to help, not pretend the object is inert.

## Hint ladder template

| Level | Reveal | Example |
| --- | --- | --- |
| 0 | Normal inspectable facts | “The vane bears three arrow-shaped notches.” |
| 1 | Direct attention | “The largest notch is aligned with the mural's river source.” |
| 2 | Reveal relation | “The first rain must reach the reservoir before the outlet opens.” |
| 3 | Concrete next move | “Try turning the upper vane toward the reservoir symbol.” |
| 4, opt-in | Reveal/bypass with consent | “Show complete solution” or “Take the service route.” |

Hint selection must be authorized (world/character scope) and not reveal an unvisited room to another player. Hints can be conditional on discovered clues rather than time. Maintain a no-spoiler player-facing narrative, with GM-only solution separated in author files.

## Tabletop variant

In a live D&D-style session, a good improvisation that logically satisfies world properties should have a fair chance; the designer prepares rules, not exclusively exact utterances. Use meaningful check outcomes to change information, cost or execution; don't gate a necessary conclusion behind one die result. When a class ability trivializes the intended puzzle, embrace it as a resourceful solution if the rules allow it.
