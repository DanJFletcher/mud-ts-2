# Orraveth Content Capability Inventory

This inventory reflects the checked-in contracts, plugins, client SDK, and server registry. “Available” means the capability is exercised through a real engine command or query, not merely described in content.

| Capability | Export / source | Input → output or event | Version and authority | Scope / permission | Status and evidence |
| --- | --- | --- | --- | --- | --- |
| World content schema | `WorldPackDraftSchema`, `validateDraftWorldGraph` in `engine-contracts/src/world.ts` | Pack draft → parsed pack and graph validation errors | Contract format v1; validated when the world package loads | Static world definition | **Available.** Orraveth pack uses the same schema and graph validator as the demo. |
| Runtime registration | `registeredWorlds`, `createWorldRuntimes` in `apps/server/src/world-registry.ts` | World instance ID → isolated runtime and plugin host | Server-controlled | Instance; access checked by server | **Available.** Orraveth has a separate stable instance ID and independent engine host. |
| Authenticated content publication | No public authoring/import endpoint found in the server routes or client SDK | Would require validated pack activation | No supported contract found | Admin / world instance | **Absent.** This slice is checked-in content, not a live-editable or dynamically publishable pack. |
| Describe current room | `location.describe` and `LocationProjectionSchema` in `engine-contracts/src/world.ts`; `characterPlugin` in `packages/plugins/src/character.ts`; SDK `look()` | Character query → current location, description, exits, local objects, NPCs | Query v1; server derives the viewer-authorized projection | Character in its selected world | **Available.** The integration test reads the initial and mill locations via the engine query. |
| Move through an exit | `MoveCharacterCommandSchema` in `engine-contracts/src/movement.ts`; `movementPlugin` | Exit ID and expected character revision → `character.moved` | Command v1; server validates exit and expected revision | Character | **Available.** The integration test travels the route and replays visited locations. |

| NPC dialogue | `NpcTalkQuerySchema`, `NpcDialogueChoiceCommandSchema`, and `NpcDialogueDefinitionSchema` in `engine-contracts/src/world.ts`; `npcDialoguePlugin` | NPC/topic query → dialogue and available choices; choice ID + expected revision → dialogue-choice event | Query/command/event v1; server verifies NPC presence and choice availability | Character; choices and quest progress are character-scoped | **Available.** Anwen's accept/report choices are exercised end to end. |
| Character quest journal and transitions | Quest contracts in `engine-contracts/src/quests.ts`; `projectQuestJournal` in `packages/engine-core/src/quest-projection.ts`; `npcDialoguePlugin` | Accept/turn-in dialogue action → `quest.accepted` / `quest.completed`; read/visit observations determine supported objectives | Events v1; server-authoritative and replayable | Character for this quest; party scope is separately supported | **Available for this slice.** Read-object objective and completion are verified in the integration test. |

| NPC relationships / reputation | No relationship state or adjustment command found in the checked-in public contracts | Not defined | No contract version | Unclear | **Absent for this slice.** Do not simulate relationship changes in dialogue text. |
| Dynamic world time / scheduled events | No public authoring or scheduler contract used by this slice | Not defined here | No contract version required | Unclear | **Not required.** No wall-clock or client-timer behavior is added. |
| Random encounters / combat | Combat plugins and contracts exist, but this pack declares no encounters | No encounter definitions in the Bellwold pack | Existing combat contracts | Character / encounter | **Available in the engine, excluded from this slice.** |

## Verification coverage

`apps/server/src/orraveth-world.integration.test.ts` validates the pack graph, checks that every Bellwold room is reachable using supported directions, then exercises room description, movement, NPC dialogue, quest acceptance, readable-object interaction, quest turn-in, and event replay.

## Architectural limits

The world package is a versioned TypeScript content pack consumed by the server registry. There is no public admin publishing workflow in this repository. Adding dynamic authoring, relationships, or new world-state mechanics requires an explicit engine contract and authorization design; content must not bypass those boundaries with direct database mutation.
